# BERX 5D — что нужно, чтобы закрыть дизайн на всех платформах

Документ отвечает на один вопрос: **что вы должны мне дать**, чтобы я довёл
дизайн BERX до состояния, в котором он работает на web, iOS, Android,
desktop, tablet, watch и AR/VR — целиком, без заглушек, с настройками,
прогрессией, бизнес-дашбордом и админ-панелью.

Всё, что ниже, разделено на четыре вида:

* **БЛОКЕР** — без этого соответствующая часть физически не проверяется.
* **ВНЕШНЕЕ** — сервис, которого нет в репозитории и который нельзя написать.
* **ВАШЕ РЕШЕНИЕ** — выбор, который не мой: продукт, деньги, рынки, право.
* **МОЯ РАБОТА** — то, что я делаю сам, как только предыдущее закрыто.

---

## 0. Одна честная рамка

Дизайн не покупает первое место. Первое место в социальной системе решают
три вещи, и дизайн — только третья: **кто на платформе есть** (сеть и
плотность связей), **что здесь можно сделать такого, чего нельзя в другом
месте**, и **насколько это не больно**. Дизайн отвечает за третье
полностью и за второе наполовину — он делает 5D читаемым, а не
аттракционом.

Что дизайн действительно может дать BERX: **узнаваемость с одного кадра**
(ни одна крупная соцсеть не выглядит как пространство), **удержание через
непрерывность** (мир не перезагружается между экранами) и **осмысленную
редкость** (#4FD6E8 значит «сейчас» и больше ничего). Это — реальные
рычаги. Я довожу их до конца. Ниже — что для этого нужно.

## 1. БЛОКЕРЫ: физика среды

Сейчас закрыто 8 launch-требований из 33. **Все восемь — не код, а
отсутствие устройства, SDK или драйвера.** Код под них написан и
компилируется; не хватает того, на чём его запустить.

### 1.1 Устройства (нужны физически, не эмуляторы)

| Что | Зачем именно | Что разблокирует |
|---|---|---|
| iPhone 12 и новее (2 шт: один старый, один новый) | Metal-путь, ARKit, тактильные отклики Taptic, реальные 120 Гц | `ios-metal`, `arkit`, `haptics-device-verification`, `real-device-verification` |
| Android с Vulkan 1.1, arm64 (2 шт: флагман + бюджетный) | Vulkan-путь, ARCore, VibrationEffect, тепловой троттлинг | `android-vulkan`, `arcore` |
| Apple Watch Series 8+ | watchOS-таргет, размер экрана, жесты короны | `watchos` |
| Meta Quest 3 **или** Apple Vision Pro | OpenXR-сессия, реальная стерео-развёртка, комфорт при движении | `openxr` |
| Mac с Apple Silicon (или доступ к macOS CI-раннеру) | Xcode-тулчейн; без него `cargo check` для iOS падает на `xcrun` | сборка iOS вообще |
| iPad Pro | планшетная раскладка, не «растянутый телефон» | tablet-форма |

Бюджетный Android нужен не для галочки: **все решения о LOD, бюджете
объектов и о том, где отключать объёмный свет и частицы, принимаются по
худшему устройству**, а не по флагману.

### 1.2 Аккаунты и подписи

* Apple Developer Program — $99/год. Без него нет ни TestFlight, ни
  подписи, ни ARKit на устройстве.
* Google Play Console — $25 единоразово.
* Сертификаты подписи кода для macOS (Developer ID) и Windows (EV code
  signing) — сейчас `desktop-signing` заблокирован именно этим.
* Учётка Meta Horizon / Quest developer — для sideload на гарнитуру.

### 1.3 Тулчейны

* Android SDK + NDK (r26+) — сейчас крейт **компилируется** под
  `aarch64-linux-android` (1 013 536 байт реального AArch64-кода), но
  линковка `.so` и сборка APK требуют NDK/SDK, которых здесь нет.
* Xcode 15+ на macOS.
* Драйвер с рабочим WebGPU-present. Здесь устройство теряется на первом
  present — это ограничение драйвера, не кода: offscreen-путь WebGPU
  совпадает с WebGL2 до 0.02/255.

## 2. ВНЕШНЕЕ: сервисы, которых нет и которые нельзя написать

Это то, что сейчас честно записано как BLOCKED «no provider exists».

| Сервис | Зачем | Что именно нужно от вас |
|---|---|---|
| **Карты** | Places, Nearby, Social Map, City Mode — четыре региона мира стоят на геоданных | Аккаунт Mapbox **или** self-hosted MapLibre + тайлы; ключ и лимиты. Нужен **векторный** источник: растровые тайлы в 5D-мире выглядят как наклейка |
| **Платежи** | Premium, бизнес-подписки, офферы. Таблицы `ossn_business_subscriptions` есть, провайдера нет | Stripe (web/desktop) + App Store IAP + Google Play Billing. Apple/Google возьмут 15–30% — это влияет на дизайн цен |
| **Push** | Notifications за пределами открытой вкладки | APNs-ключ (.p8), FCM-проект. Web Push — VAPID-пара |
| **Медиа-хранилище/CDN** | Фото и видео. Сейчас медиа лежит локально у OSSN | S3-совместимое хранилище + CDN. Нужны лимиты и политика хранения |
| **Транскодирование видео** | Один залитый файл ≠ проигрываемый на всех платформах | Сервис или ffmpeg-воркер + профили (HLS, 3 битрейта) |
| **Почта** | Активация, сброс пароля, дайджесты. OSSN шлёт через PHP mail() | SMTP-провайдер (Postmark/SES), домен, SPF/DKIM/DMARC |
| **TURN/STUN** | Только если будут голос/видео-звонки | coturn или платный TURN |
| **Модерация контента** | Обязательна для App Store и Google Play при UGC | Провайдер авто-модерации изображений/текста **или** ваше решение делать вручную (тогда нужны люди) |
| **Аналитика продукта** | Без неё дизайн улучшается вслепую | Self-hosted PostHog / Matomo. Важно: в 5D нет «экранов», события меряются регионами и переходами |
| **Прод-инфраструктура** | Сейчас всё живёт в контейнере проверки | Сервер (4+ ядра, 16 ГБ), MySQL 8/MariaDB 10.6+, PHP 8.4, домен, TLS, бэкапы |

## 3. БРЕНД И КОНТЕНТ: то, что дизайн не имеет права выдумать

### 3.1 Типографика — **самый срочный пункт**

Сейчас в коде **намеренно не назван ни один шрифт**
(`typography.ts`: «BERX ships no bundled face»). Шкала из 10 ролей есть,
гарнитуры нет. Мне нужно:

* Лицензированная гарнитура с правом embedding в приложение и в
  desktop-бинарь, с кириллицей и латиницей, минимум 4 начертания
  (400/600/700/800), желательно variable.
* Отдельно — моноширинная для чисел (метрики, счётчики) с
  **табличными цифрами**: без них цифры в дашборде прыгают.
* Файлы в `.woff2` (web) и `.ttf`/`.otf` (native), плюс текст лицензии.

Без этого мир рендерит имена системным шрифтом — и BERX выглядит как
чужое приложение на каждой платформе по-разному.

### 3.2 Логотип и знак

* Векторный знак BERX в SVG: монохром, на тёмном, минимум 3 размера
  (16/24/512), плюс версия для favicon и для иконки приложения по
  гайдлайнам Apple/Google.
* Правило: знак **не** светится `#4FD6E8` по умолчанию — этот цвет
  зарезервирован под «сейчас».

### 3.3 Фото и видео

В репозитории уже есть `assets/media/atmosphere/` — этого мало.
Нужно: **50–100 лицензированных фотографий** реальных мест, людей и
событий под сид-контент и под скриншоты сторов. Требования: тёмные,
контрастные, без стоковой улыбки в камеру. Дизайн, собранный на серых
плейсхолдерах, разваливается на реальном контенте.

### 3.4 Звук

5D-мир без звука наполовину мёртв. Нужно 12–16 коротких звуков
(≤400 мс, 48 кГц): фокус, переход, прибытие, назад, действие принято,
действие отклонено, появление сущности, «сейчас»-импульс, сообщение,
уведомление. Либо композитор, либо лицензированная библиотека. Тактильные
паттерны у меня уже есть — звук должен ложиться на них по времени.

### 3.5 Голос продукта и юридические тексты

* Тон: сейчас интерфейс на русском. Нужно решение по языкам (см. §4).
* Юридические тексты: Условия использования, Политика приватности,
  Правила сообщества, политика по данным несовершеннолетних. **Их
  пишет юрист, не я.** Без них приложение не пройдёт ревью в сторах.

## 4. ВАШИ РЕШЕНИЯ: без них я буду выбирать за вас

1. **Модель денег.** Premium-подписка? Бизнес-подписка? Реклама? Комиссия
   с событий? От этого зависит, есть ли в мире рекламная поверхность
   вообще — а это архитектурное решение, не косметика.
2. **Цена и валюты.** Тариф Premium, тариф для бизнеса, пробный период.
3. **Рынки и языки.** Сейчас интерфейс русский. Каждый язык — это не
   перевод, а раскладка: немецкий длиннее русского на ~30%, арабский
   требует RTL всего мира, включая направление колец действий.
4. **Возрастной рейтинг** (13+/17+) — определяет, нужен ли возрастной
   гейт, родительский контроль и режим для подростков.
5. **Политика модерации**: что удаляется, кто решает, есть ли апелляция.
   Это форма админ-панели, а не её настройка.
6. **Приватность по умолчанию**: профиль публичен или закрыт при
   регистрации. Это меняет весь онбординг.
7. **Что такое «живое»** для BERX Energy. Сейчас порог — реальный
   серверный сигнал. Вам решать, что считается событием «сейчас».

## 5. СОСТАВ КОМПОНЕНТОВ — от А до Я

### 5.1 Что уже стоит (проверено, не обещано)

* **Рантайм 5D**: один мир — `Berx5DWorldApp → Berx5DRuntime → Berx5DFrame
  → WorldGraph → SpatialIdentity → TemporalSystem → RelationalGraph →
  адаптер → рендерер`. Три GPU-бэкенда сходятся попиксельно (native vs
  WebGL2 — 99.76% IoU).
* **Свет**: PBR (GGX + Smith + Schlick), тени во всех трёх бэкендах,
  аналитическое окружение, SSAO, объёмный свет, частицы (пыль, энергия,
  звёзды) — всё детерминировано, всё сверено с CPU-оракулом.
* **Ткань интерфейса**: 97 собственных SVG-иконок, шкала из 10 ролей,
  палитра из 9 цветов, 6 temporal-палитр, 11 видов атмосферы, 8 переходов,
  5 тактильных паттернов, пространственное аудио.
* **Мир**: 13 регионов, 10 видов сущностей, 7 типов связей, кольцо
  действий, world-space имена.
* **Бэкенд**: 55 ресурсов `/api/v1`, realtime по WebSocket, 73 таблицы.
* **Компоненты**: 69 пространственных React-компонентов в design-system.

### 5.2 Регионы мира — что должно быть в каждом

13 регионов уже определены в рантайме. Для каждого мне нужно от вас
**только §3 и §4**; остальное — моя работа. Полный состав на регион:

| Регион | Что это | Состояния, которые надо нарисовать |
|---|---|---|
| `world` | точка входа, весь граф | первый вход, пустой граф, плотный граф, потеря сети |
| `now` | что происходит прямо сейчас | есть живое / тихо / только у друзей |
| `discover` | люди и места, которых вы не знаете | рекомендации, пусто, отказ от рекомендаций |
| `person` | человек как место | свой / друг / не друг / заблокирован / удалён |
| `place` | место | обычное / бизнес / закрыто сейчас / без фото |
| `event` | событие | будущее / идёт / кончилось / отменено / нет мест |
| `experience` | совместный опыт | приглашение / принято / идёт / архив |
| `community` | сообщество | участник / гость / закрытое / заявка на рассмотрении |
| `collection` | подборка | своя / чужая / пустая |
| `conversation` | разговор | 1:1 / групповой / набор текста / непрочитанное / архив |
| `create` | создание чего угодно | 9 типов сущностей, черновик, ошибка загрузки |
| `signals` | уведомления и реакции | новые / прочитанные / сгруппированные / пусто |
| `self` | вы сами | профиль, прогресс, настройки, данные |

**Каждый регион × 4 форм-фактора** (phone / tablet+desktop / watch / XR)
и × 3 состояния данных (загрузка / есть / нет) — это и есть настоящий
объём дизайна. Плюс: reduced motion, высокий контраст, RTL, крупный шрифт.

### 5.4 Чекпоинты (прогрессия)

Уточню, потому что слово используется в проекте в двух смыслах:

* **Внутренние чекпоинты верификации** — матрица 300×133 в
  `scripts/max-checkpoints.mjs`. Это инструмент, пользователь его не видит.
* **Продуктовые чекпоинты** — то, что вы имеете в виду. Основание уже
  есть: `OssnPoints`, `missions.php`, `identity.php` с реальными
  счётчиками (мест отмечено, событий посещено, поездок создано…).

Что надо спроектировать:

1. **Путь первых 7 дней** — 8–10 шагов, каждый разблокирует часть мира,
   а не выдаёт значок. В 5D это буквально: мир становится больше.
2. **Уровни присутствия** — не «очки», а расширение того, что вы можете
   в мире: радиус видимости, число одновременных связей, доступ к
   созданию событий.
3. **Ежедневные миссии** — API есть (`missions.php`), нужна форма.
4. **Достижения** — выводятся из реальных счётчиков, не хранятся отдельно.
5. **Годовой Wrapped** — API есть (`wrapped.php`), это сильнейший
   вирусный носитель, и в 5D он должен быть **пролётом через свой год**,
   а не набором карточек.

От вас нужно: **§4.7** — что считается достижением, и не превращаем ли мы
это в казино. Механики удержания, построенные на тревоге, поднимают DAU и
разрушают репутацию — я предложу вариант без них.

### 5.5 Бизнес-дашборд

Есть 6 экранов и реальные таблицы (`ossn_place_claims`, `ossn_business_team`,
`ossn_business_offers`, `ossn_nearby_impressions`, `ossn_place_hours`).
Нужен полный состав:

* **Заявка на место** — подтверждение владения, статусы, отказ с причиной.
* **Профиль бизнеса** — часы (есть), контакты, фото, категории, «сейчас
  открыто» как состояние мира, а не как строка.
* **Моменты** (`ossn_business_moments`) — «что у нас сейчас»: это прямая
  дорога к BERX Energy и главное отличие от Instagram-профиля.
* **Офферы** — создание, лимиты, погашение, срок.
* **Аналитика** — показы / открытия / сохранения / маршруты
  (`ossn_nearby_impressions` уже пишет эти четыре). Нужны: график по дням,
  сравнение с прошлым периодом, разрез по источнику.
* **Отзывы** (`ossn_place_reviews`) и **ответы владельца**
  (`ossn_place_review_replies`) — есть в схеме.
* **Команда и роли** — есть таблица, нужны роли и права.
* **Подписка и счета** — ← НЕТ провайдера (§2).
* **Реклама** — ← только если §4.1 скажет «да». Это отдельная система.

**Для дашборда мне нужно от вас:** какие метрики вы обещаете бизнесу.
Показывать «просмотры» без определения — это то, за что соцсети судят.

### 5.6 Админ-панель

Сейчас на бэкенде **5 действий**: `unvalidated`, `validate`, `ban`,
`unban`, `dating-unhide`. Для настоящей соцсети нужно:

* **Очередь жалоб** — `ossn_reports` есть; нужны приоритет, SLA,
  назначение на модератора, массовые действия.
* **Карточка пользователя** — история, связи, устройства, санкции.
* **Градация санкций** — предупреждение / ограничение / заморозка / бан,
  с длительностью и причиной. Сейчас только бинарный бан.
* **Апелляции** — ← НЕТ. Без них бан необратим, а это претензии и иски.
* **Снятие контента** — с сохранением копии для расследования.
* **Журнал аудита** — ← НЕТ. Кто, что, когда, зачем. Обязателен.
* **Роли и права** — сейчас только «админ». Нужны: модератор, поддержка,
  аналитик, супер-админ.
* **Флаги функций** — включить регион мира части пользователей.
* **Объявления** — сообщение всем или сегменту.
* **Метрики здоровья** — регистрации, удержание, жалобы на 1000
  пользователей, время до решения по жалобе.
* **Инструменты доверия** — обнаружение массовых регистраций, спама,
  накрутки. ← отдельная работа, не дизайн.

**От вас: §4.5** — политика. Форма админ-панели вытекает из неё, а не наоборот.

### 5.7 Платформенные оболочки

| Платформа | Что уже есть | Что нужно спроектировать |
|---|---|---|
| Web | полный рантайм на WebGL2 | клавиатурная навигация мира, курсор, PWA-установка |
| Desktop | нативный бинарь, .deb собирается и запускается | окна, меню, горячие клавиши, трей, обновление |
| iOS | Swift-обвязка над Rust, SwiftPM | нативная оболочка, разрешения, Live Activity, шаринг |
| Android | Java + JNI, Gradle | то же + виджеты, Intent-и |
| Tablet | форма описана в ядре | двухпанельная раскладка: мир + контекст |
| Watch | ничего | **новый таргет**: только «сейчас», короткие ответы, корона как ось T |
| AR | код позы и стерео есть | якоря, плоскости, окклюзия реальным миром, комфорт |
| VR | стерео рисуется | контроллеры, лучи, теплокомфорт, safe area, сидя/стоя |

**Про часы и XR честно:** это не «адаптация экранов». Часы — это один
регион (`now`) и ничего больше. XR — это мир без экрана вообще, где
кольцо действий становится буквально досягаемым рукой. Каждый из них —
отдельный дизайн-проект на 3–6 недель.

## 6. Порядок: что что разблокирует

1. **Шрифт + логотип + звук** (§3.1–3.4). Разблокирует всё остальное:
   пока нет гарнитуры, каждый экран придётся переделывать после её выбора.
2. **Решения §4** — особенно модель денег и языки. Они меняют структуру,
   а не оформление.
3. **Прод-инфраструктура + почта + медиа-CDN** (§2). Без них нельзя
   показать дизайн на реальных данных, а на плейсхолдерах он врёт.
4. **Карты** (§2) — разблокирует 4 региона из 13.
5. **Устройства и аккаунты** (§1) — разблокирует 8 из 8 закрытых
   launch-требований. Это единственный путь снять их: код уже написан.
6. **Платежи** (§2) — разблокирует Premium и бизнес-подписку.
7. **Юридические тексты** (§3.5) — без них нет релиза в сторах.
